# 经验：群聊接力（多 Agent 协作）的设计与踩坑

状态：经验沉淀，随 relay-router.md（设计契约）配套使用。凡是做"多个 Agent 协作完成任务"的系统，这里的模式与反模式可直接复用；代码参照 `internal/app/relayrouter.go` 及其测试。

## 1. 架构：host 驱动 + 路由决策，不上消息总线

**模式**：接力 = 一个持久化转录 + 一个 host 侧派发循环。每个成员回合结束后，host 做**一次路由决策**（选下一个发言者，或宣布结束），派发下一位。没有常驻编排器、没有消息总线——`finish()` → 路由 → `dispatch` 的链式循环就是全部。

**为什么**：消息总线/常驻守护把并发和生命周期管理抬一个量级；host 驱动让"Stop 一次取消全部""线程级运行注册表""转录即上下文"都是自然性质。对照 AutoGen/LangGraph 的编排器对象图，这个极简循环覆盖了 90% 的需求。

**复用原则**：先做"转录 + 循环 + 决策点"，编排基础设施等到循环本身不够用时再上。

## 2. @点名：一个语法，三个入口，必须防回声

**模式**：`@成员名` 统一语法，`extractMentions`（按出现顺序、去重）供三处共享：输入框新消息（点名即首棒）、运行中插话（点名是路由指令，不是普通上下文）、成员回复（直通交接/并行 fan-out）。

**踩坑：mention 回声（本项目最隐蔽的 bug）**。成员回复必然**引用**请求里的 @（"先回应 @A 的建议"）。路由逻辑对每条落定回复重新提取 @，就把回声当成了新交接——同一成员被反复派发（测试复现：两人各跑 4 遍），且每跳都旁路协调者，形成**轮数兜底的死循环**。

**修法**：`honored` 集合——**成员发起的 mention 每回合对每个成员只生效一次**，之后回落协调者；**用户亲自 @ 不受限**（用户说两遍就是两遍，这是用户权威）。

**复用原则**：凡是"从内容里提取指令"的系统，内容会引用历史指令——提取器必须有每回合的一次性记忆，且区分"用户发的指令"与"内容里的引用"。

## 3. 并行 fan-out：隔离，而不是共享

**模式**：被点名的多个成员并发运行，每人独立消息槽；**全部落定后才做下一次路由决策**。

**踩坑：共享可变上下文**。两个并发成员往同一份共享转录（ChatLog）里写，互相覆盖/交错，是正确性灾难。**修法**：每个并发成员持有一份 fork（派发时刻的快照 + 私有增量），落定时按完成顺序把私有后缀并回共享历史。

**第二个坑**：共享会话的成员（CLI 后端共用一个会话 id）不能并发——排在并发批次之后串行。

**测试方法**：并发断言不要用 barrier channel（晚到的第三方请求——比如总结回合——会把 handler 永久卡死，`srv.Close()` 连带整个测试挂死）。改用**到达时间重叠断言**：记录每个请求的到达时刻，断言第二个的到达早于第一个的完成（响应统一延迟 300ms）。串行派发必然失败，无死锁风险。

**复用原则**：并发成员的上下文要么 fork-then-merge，要么串行；"共享可写状态 + 并发"没有第三条路。测试并发用时间重叠，别用会卡死服务的 barrier。

## 4. 路由决策：模型选型与提示词

**三条线的实测结论**：

- **chat 线**（任意 OpenAI 兼容模型 + JSON 提示词）：最通用。两个必备件：宽容解析（严格 JSON → 剥 ``` 围栏 → 剥夹文本）、名字念错时的一次纠正往返。
- **decision 线**（Jev 决策模型如 tev1，`/v1/systemone`）：选项即成员名，回答受约束、带概率，不可能念错名字。**但**上下文只有 ~2k token，喂不了完整对话；对单薄摘要倾向判"完成"（根因：尾部摘要丢了用户原始请求，"请求是否已解决"无从判断）。
- **hybrid 线**（大模型写态势简报 → 决策模型裁决）：正确形态。大模型负责理解，决策模型负责受约束的最终裁决；advisor 失败降级为 decision 线，不是单点依赖。

**提示词三件套（缺一则路由退化）**：

1. **轮次状态放在摘要前面**（会被截断的是尾巴）：`第 N 轮，发言顺序：X → Y。尚未发言：Z。`——没有它，连公平轮转都是瞎猜；点名状态要由状态机记录（`relayState.spoken`），不能靠模型自己数。
2. **用户的原始请求单独放**——尾部摘要会把它挤掉，而"请求是否已解决"没有它无从回答。
3. **done 题必须排除"留白式提问"**：成员以提问/开放选项收尾 ≠ 完成，只要面板里有人能拍板就继续——否则成员把选择题抛给用户，协调者顺势收场，任务悬在空气里。

## 5. 面板协议：成员决定，不甩锅

**踩坑**：成员提示词是对着人写的，遇到选择题的本能是"要哪个，或者你说了算"——面板当场停摆。

**修法**：派发时在成员 system prompt 的**拷贝**上追加面板协议：遇到选择给明确推荐（方案+理由+成本），让面板推进；只有真正的业务取舍才留给用户，且即便如此也先给推荐。**三个关键点**：用拷贝不污染原档案（路由依据、设置页读的仍是干净版本）；codex 类忽略 system prompt 的后端改走交接词文本（先查证每个适配器实际消费哪些字段！）；协议同时教成员 `@点名` 语法——成员知道谁是下一位时直通交接，省一次路由调用。

## 6. 护栏：三层兜底，优雅降级

- **硬护栏先于一切智能**：轮数上限、token 预算（从成员回合的用量累计汇入）、墙钟超时、同名连讲上限——全部在路由决策**之前**评估，协调者无法说服它们放行。同名连讲阈值别设太小（3 会掐死真正连续干活的执行者，5 合理）。
- **降级即终点**：协调者调用失败（超时/坏 JSON/念错名字）→ 落 note → 结束接力。**绝不因路由器挂掉把用户卡在运行态**。超时给足 2 分钟——推理模型读长摘要超过 30 秒是正常的，别把健康路由掐成"协调者不可用"。
- **结束要可见**：判完成/护栏触发/降级，原因都落成 note；结束前加**总结回合**（指定总结者或绑定 agent）写面向用户的结论——接力结束在最后一个专业角色的发言上，用户就得自己拼结论。
- **所有护栏可配置**（零值=默认），但默认值本身就是调参结论。

## 7. 可观测性与回归：提示词改一处，路由行为全变

- **路由决策进 trace**：选了谁/为何失败、耗时、token 成本——协调成本不可见就不可优化。
- **黄金回归集**：脚本化场景（固定转录+轮次状态 → 期望的 next **集合**或 done），门控在环境变量后跑真模型。断言必须是**性质**（接受名字的集合、"已发言者不得重复"的负向断言），不钉死唯一答案——真模型是概率性的，钉死名字的黄金集会按日程表失败。
- **header 预算可见**：运行中显示轮数与 token 烧蚀，护栏从暗桩变仪表。

## 8. 转录 UI：工作日志的可读性

实测一条成员消息 55 个 block（命令/思考/散文交错）的教训：

- **按种类跨位置折叠**，别按相邻 run——工作日志天然交错，相邻折叠只剩一圈塌行。同种类 ≥2 次全部折进一个组（"5 commands · 4.1s"），散文保持原位；一次点击开/关该种类全部。error/approval 刻意不折叠。
- **heredoc 写文件自动展开**：成员通过 `cat > f <<EOF` 写代码时，内容在命令文本里、标题单行截断、输出近空——不展开等于工作成果不可见（用户报告："点击没有命令行，全都收起来了"）。多行命令落定即展开，展示完整命令文本。
- **流式全程有 spinner**（内容到了也不撤）；**markdown 全部 Selectable**（不能复制是硬伤）。

## 9. 测试复盘（本项目真实踩的）

- fixture 的共享变量（请求体记录、计数器）必须加锁——HTTP handler goroutine 与测试主 goroutine 的数据竞争只在 `-race` 全量下偶现。
- 时序断言：等"落定"用轮询 `!isRunning && queue==nil`，别在中间状态断言（第二次路由调用可能还在途）；复用外层 deadline 变量会造出 20 秒的假 sleep。
- provider 失败模拟要罩住内层重试：`doWithRetry` 自己会重试 500 三次，fixture 只让第一次请求失败时，失败根本到不了外层逻辑。
- Perl/正则批量改测试文件前先确认调用点形状——一次误删六个函数声明行，靠 `go vet` 才发现。

## 10. 迭代路径（复用此模式时的推荐顺序）

1. 固定顺序接力（骨架：转录+循环+派发）→ 2. 路由决策（chat 线起步）→ 3. 护栏+降级 → 4. 轮次状态+面板协议（路由质量的地基）→ 5. 点名/直通交接/并行 fan-out → 6. 总结回合 → 7. trace+黄金集 → 8. UI 打磨。

每步都可独立交付且向后兼容：旧配置（无 `panel_route`）行为不变，这是全程没破坏一次现有测试的关键。
